## How it works

A 112-byte memory (896 bits) built from **3T gain cells** (gain-cell eDRAM): each bit is the
charge on a transistor's gate, written through a PMOS and read through a separate two-transistor
read port, in plain sky130 logic devices -- no capacitor, no special SRAM rules. The macro (one bank
of 16 rows x 56 columns, 150.9 x 77.3 um, with a replica column that times every
read) was generated by [gc_compiler](https://github.com/barakhoffer/gc_compiler), and signed off
with magic/KLayout DRC and netgen LVS; the refresh controller beside it is synthesized Verilog from
the same compiler.

A row is 7 bytes, and a write writes one byte of it: the macro reads the row with every bit
line held, precharges the written byte's bit lines again, and writes -- the written byte's columns
take the new data, and every other column writes back the bit it just read.

The charge leaks, so every row is refreshed in the background: a timer asks for the next row
every few microseconds, and one ordinary access -- a read whose bit lines hold the row's data, then
a write that puts each column's own bit back -- restores it inside the macro. A pending refresh
takes the memory at the next idle cycle (`busy` is high meanwhile).

## How to test

Pins: `ui_in[3-1:0]` the byte in the row (0 to 6), `ui_in[5:3]` the row's
low bits, `ui_in[6]` we, `ui_in[7]` req, `uio[7:0]` the data bus, `uo_out[0]` busy, `uo_out[1]`
dout_valid, and `uo_out[1+1:2]` the page: the row's top 1 bits.

1. Set the page: a write to byte 7 (a row has no such byte) sets it from `uio_in[1-1:0]`. It holds until the next
   such write or a reset.
2. Wait until `busy` is low, then set the address, `we` (1 to write) and -- for a write -- the data
   on `uio_in`, and raise `req` for one rising `clk` edge.
3. Keep the address, `we` and the data until `busy` is low again.
4. A read's data is on `uio_out` (the chip drives `uio` whenever `we` is low) from the cycle
   `dout_valid` pulses, and stays until the next request.

The clock is 50 MHz. Data survives without any access: refresh runs on its own as long as `clk`
runs and `rst_n` is high.
