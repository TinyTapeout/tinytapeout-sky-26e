## How it works

A configurable discrete **8-bit PID controller**. A host MCU (for example the
RP2040 on the demo board) writes a setpoint SP and a measurement FB (both 0–255).
The chip computes the control action U (0–255) and puts it **as a number on
`uo_out`**, where it stays until the next sample.

```
e[n]  = SP - FB              (or FB - SP when REV = 1)          9-bit signed
I[n]  = clamp(I[n-1] + Ki*e[n], 0, 255)      conditional integration (anti-windup)
U[n]  = clamp(round(Kp*e[n] + I[n] + Kd*(e[n]-e[n-1])), 0, 255)
```

* Gains Kp, Ki, Kd: 12-bit unsigned fixed point **UQ4.8** (value / 256, so 0 to 15.996).
* 16-bit integrator (UQ8.8) and 23-bit accumulator. The accumulator cannot overflow for any input.
* Anti-windup: the integrator is clamped to [0, 255], and integration is skipped while the output is saturated in the direction of the error.
* Sampling: internal 12-bit timer (period TS+1 clocks), external pin, on every FB write, or software command.
* A single serial shift-add MAC computes the three products: **39 clock cycles per sample** (BUSY is high for 38).
* Reset is asserted asynchronously and released synchronously, so the outputs go to 0 at once, even without a clock.

### Bus protocol (write only)

`ui_in` carries a byte. `uio[1]` (AD) selects an address cycle (1) or a data cycle (0),
and a rising edge on `uio[0]` (WR) performs the cycle. Data writes auto-increment
the address. 12-bit registers are written low byte first, then the high byte
(bits [3:0]); the register changes only when the high byte arrives. WR must be
high for at least 4 clocks and low for at least 4 clocks, and D/AD must be
stable while WR is high.

| Addr | Register | Reset | Notes |
|---|---|---|---|
| 0x0 | CTRL | 0x02 | [0] EN, [1] AW_EN, [2] REV, [4:3] TICK_SRC (00 timer, 01 ext pin, 10 FB write, 11 software only) |
| 0x1 | CMD | – | [0] SW_TICK, [1] CLR (clears the integrator and the previous error) |
| 0x2 | SP | 0 | setpoint 0–255 |
| 0x3 | FB | 0 | feedback 0–255; starts a sample when TICK_SRC = 10 |
| 0x4/0x5 | KP | 0 | UQ4.8 |
| 0x6/0x7 | KI | 0 | UQ4.8 |
| 0x8/0x9 | KD | 0 | UQ4.8 |
| 0xA/0xB | TS | 999 | sample period - 1 (in clocks) |

### Status outputs

| Pin | Signal | Meaning |
|---|---|---|
| `uio[3]` | HOLD | anti-windup skipped the integration in the last sample |
| `uio[4]` | DRDY | a new U is ready; cleared by the next write or the next sample |
| `uio[5]` | SAT_HI | U was clipped at 255 |
| `uio[6]` | SAT_LO | U was clipped at 0 |
| `uio[7]` | BUSY | computation in progress |

## How to test

1. Reset. `uo_out` = 0 and `uio[7:3]` = 0.
2. Write KP = 256 (1.0), KI = 0, KD = 0: address cycle 0x4, data 0x00, data 0x01, data 0x00, data 0x00, data 0x00, data 0x00.
3. Write CTRL = 0x13 (EN, AW_EN, TICK_SRC = FB write) and SP = 100.
4. Write FB = 40. After 39 clocks DRDY (`uio[4]`) goes high and `uo_out` = 60.
5. For a closed loop: in every sample, read the sensor with the host, write FB, wait for DRDY and send `uo_out` to the actuator (for example through an 8-bit R-2R DAC or as a PWM duty cycle generated by the host).

## External hardware

None required. For a real closed loop you need a sensor read by the host MCU
and an actuator driven from the 8-bit `uo_out` value.
